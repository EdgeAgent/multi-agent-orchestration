# Persistent Memory and "Work-as-Git" Local Workspaces

Managing state across extended execution graphs presents severe context window overflow challenges and scalability bottlenecks. Traditional cloud architectures rely heavily on external database infrastructure such as PostgreSQL or Redis, which introduce network latency, serialization overhead, and complex infrastructure dependencies. To address these limitations, modern orchestration frameworks increasingly adopt local-first, file-backed workspace designs that eliminate external database dependencies entirely.

Architectures such as OpenAlice reflect this operational shift by managing agent tasks, execution sessions, and persistent memory directly within local filesystem trees (`~/.openalice`) backed by local Git repositories. Task tracking is implemented through self-describing, version-controlled Markdown issues stored in `.alice/issues/`, enabling full historical auditability and native branch-based task isolation. Long-term persistent memory is maintained as an interlinked knowledge graph of Markdown documents using bidirectional references (`[[entity_name]]`), mirroring the structure of Obsidian-style knowledge bases.

Furthermore, trade orders, execution payloads, and system modifications are written to disk as staged files within `.alice/staged/` and committed locally via Git. Execution remains strictly gated until a human administrator reviews the changes, signs off, and approves the commit hash. This "Work-as-Git" paradigm ensures absolute transparency, reproducible execution states, and robust human-in-the-loop governance without compromising agent autonomy.
